Stacking vs portaled nav

Cheat sheet for why HorizontalScroll’s panel x defeats in-panel z-index, and how DesktopNavbar morphs on perfect rail overlap.

Actors

document.body
  └─ DesktopNavbar (portal)     fixed + z(--znavbar)     ← always viewport-left

main[containerRef]  pin
  div[panelsRef]    transform: translateX(...)          ← stacking context
    …panels…
    Portofolio
      #portofolio-nav-rail       absolute left rail
        DesktopNavbar sticky invert

Why raising z-index failed

  • Non-none transform → new stacking context (atomic unit in parent).
  • Child z-index only compares inside that context.
  • Body portal is a sibling of the transformed tree → paints above it regardless of portfolio z-index: 60.

Shipped rule

rail.left <= 1px  →  fixed nav bg-brand-dark (+ 300ms transition)
rail.left > 1px   →  fixed nav bg-brand-tan

Measure: #portofolio-nav-rail (not the whole section)
Keep sticky invert mounted (double-paint OK when aligned)

Not this

  • Early invert at left ≤ 72 (column touch)
  • Hide/show the portal to “win” stacking
  • Reparent / position: static into the rail
