Double-rAF enter cheat sheet

Compressed map of why nested requestAnimationFrame exists in the mobile menu open path.

State machine

Flag Role
shouldRender Portal mounted (null when false)
entered CSS class: closed -translate-y-full / opacity-0 vs open translate-y-0 / opacity-50
isOpen (prop) Parent intent — open vs close

Open timeline

isOpen → setShouldRender(true) during render
→ mount with entered=false (closed styles)
→ rAF₁ (before paint of closed)
→ rAF₂ (before next paint)
→ setEntered(true) → CSS transition runs

Close timeline

isOpen=false → rAF → setEntered(false)
→ transitionend on transform (or timeout ANIM_MS+50)
→ setShouldRender(false) + entered=false

Why double, not single

MDN: rAF fires before the next repaint. A single rAF that sets the “open” class can still share a paint with the initial closed mount — the browser never interpolates. Nesting defers the flip until after that paint.

Glossary

rAF / requestAnimationFrame
One-shot callback scheduled for the pre-paint slot of the next frame.
Double-rAF
Outer rAF schedules an inner rAF; inner runs on the following frame, after the outer’s frame has painted.
From→to (CSS transition)
Browser must compute a previous style and a new style across paints; same-paint batching skips the transition.
transitionend fallback
Timeout if transitionend never fires (e.g. tab backgrounded while rAF is paused).
