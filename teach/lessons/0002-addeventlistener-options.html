Lesson 02 · useEventListener

addEventListener options

One idea: the third argument is a small contract — when the listener runs, how often, and whether it may cancel the event.

~6 minutes · tied to hooks/useEventListener.ts lines 65–70 and useHorizontalScroll’s resize call

What your hook forwards

In useEventListener, after resolving target / enabled, the DOM call looks like this (MDN): 

element.addEventListener(eventName, listener, {
  capture,
  once,
  passive,
  signal,
});
target and enabled are hook options only — they never reach addEventListener. Your horizontal scroll uses { passive: true, enabled } so resize refreshes ScrollTrigger only on desktop, and never blocks the browser with preventDefault.

Four options, four jobs

  1. capture — run during the capture phase (top → down) instead of the bubble phase (bottom → up). Default false.
  2. once — invoke at most once, then the browser removes the listener. Default false.
  3. passive — promise you will not call preventDefault(), so the browser can apply defaults (e.g. scroll) without waiting. If you call it anyway, it is ignored (and may warn).
  4. signal — an AbortSignal; when aborted, the listener is removed.
