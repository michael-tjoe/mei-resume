Lesson 07 · MobileNavbarMenu digression

Two frames so the slide can start

One idea: CSS transitions need a painted from state. requestAnimationFrame runs before paint — so this menu nests two of them before flipping entered to open.

~7 minutes · tied to components/PortofolioNavigation/MobileNavbarMenu.tsx

Two flags, one job each

  • shouldRender — is the portal in the DOM at all?
  • entered — which transform class is on the sheet? false → -translate-y-full, true → translate-y-0.

On open, render mounts with entered === false (off-screen). Only later does the effect set entered true so the compositor can interpolate. That “later” is the rAF dance.

What rAF actually schedules

Per MDN requestAnimationFrame, the callback runs before the next repaint — not after. It is one-shot; nesting another call queues work for the following frame’s pre-paint slot.

Jake Archibald’s In The Loop (JSConf.Asia) walks the same pipeline: tasks → microtasks → rAF → style/layout/paint. Anything you schedule inside a rAF callback runs on the next frame’s rAF batch — after this frame has painted.

Why this component nests two

// isOpen path — MobileNavbarMenu.tsx
outerId = requestAnimationFrame(() => {
  if (prefersReducedMotion()) {
    setEntered(true);
    return;
  }
  innerId = requestAnimationFrame(() => setEntered(true));
});
  1. Mount paints (or is about to paint) with closed styles — -translate-y-full, overlay opacity-0.
  2. Outer rAF runs before that paint. Flipping entered here can still land in the same paint as mount — no from→to, sheet pops in.
  3. Inner rAF runs before the next paint. By then the browser has committed the closed frame, so setEntered(true) starts a real CSS transition.

The comment in the file says it plainly: paint the closed frame first, then flip — otherwise both states land in one paint. Libraries hit the same bug; e.g. Video.js’s transition open needed double-rAF for the same reason.

Feel it

Open with Instant (jumps), then Double (slides). Single is the unreliable middle — sometimes slides, sometimes pops, depending on timing.

Close is asymmetric

On close, the sheet is already painted open. One setEntered(false) is enough to start the exit transition. Unmount waits for transitionend on transform (or a ANIM_MS + 50 timeout if that event is skipped — background tab, etc.). Cleanup cancels pending rAF ids and the fallback timer so rapid open/close cannot leave stale flips.
