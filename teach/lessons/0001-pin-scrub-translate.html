Lesson 01 · HorizontalScroll

Pin, scrub, translate

One idea: the page still scrolls vertically; your panels only look like they scroll sideways.

~5 minutes · tied to components/HorizontalScroll

The trick

GSAP calls this a fake horizontal scroll: pin a section so it sticks in the viewport, then scrub a tween that moves an inner row on the x axis while the user keeps scrolling the page normally. (GreenSock’s ScrollTrigger skill; docs)

In your file that maps like this:

main[containerRef]     → pin + trigger
  div[panelsRef]       → gsap.to({ x: -distance })
    children (panels)
Official guidance: pin the wrapper; animate a child — don’t slide the pinned element itself.

Feel it

Drag the slider as if it were the vertical scrollbar. The black frame stays put (pin). The colored panels slide left (scrubbed x).

What your tween is saying

gsap.to(panelsEl, {
  x: () => -getScrollDistance(),   // how far left panels must travel
  ease: "none",                    // 1:1 with scroll — required
  scrollTrigger: {
    trigger: container,
    pin: true,                     // freeze container in the viewport
    scrub: 1,                      // progress follows scroll (1s catch-up)
    end: () => `+=${getScrollDistance()}`,
    invalidateOnRefresh: true,
  },
});

getScrollDistance() is panels.scrollWidth − window.innerWidth: exactly the overflow that must slide into view. Matching that number in both x and end keeps scroll distance and sideways travel in lockstep.

ease: "none" matters. With scrub, a curved ease makes early scroll move the panels unevenly — GreenSock calls this out as a common mistake on fake horizontal scroll.

Check yourself

While the effect is active, what is the user actually scrolling?
