Lesson 04 · loadMorphGsap

Promise cache with ??=

One idea: the first call starts the MorphSVG import; every later call reuses the same Promise — that is what line 13’s ??= does.

~5 minutes · tied to loadMorphGsap.ts lines 5–20

The line

morphGsapPromise ??= Promise.all([
  loadGsap(),
  import('gsap/MorphSVGPlugin'),
]).then(/* register + return gsap */);

??= is nullish coalescing assignment: assign the right-hand side only if the left is null or undefined. If the left already holds a Promise, the right side is not evaluated at all (short-circuit) — so no second dynamic import.

Same idea as if (morphGsapPromise == null) morphGsapPromise = …, but one expression. Not the same as ||=, which would also overwrite other falsy values.

Why cache a Promise, not the result?

Caching the Promise means overlapping first calls (enter on Game + Mic before load finishes) all await / .then the same in-flight work. Caching only after resolve would let two early callers each start a fresh import().

Module-level let morphGsapPromise lives for the whole Chalks chunk lifetime — Game, Mic, and Paint share one load (register plugin once).
